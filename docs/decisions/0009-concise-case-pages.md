# Concise case pages and report presentation

Date: 26 October 2026 (America/Chicago)

Issue: https://github.com/chineseschrodingercat/elvia/issues/21

The maintainer requested the same reading improvements across all 700 published
ICML/NeurIPS cases and their report downloads. This supersedes the earlier
decision to repeat complete report text in a separate webpage disclosure.

## Reading hierarchy

Finding at a glance contains one to three concise points, at most 80 words in
total, without repeated source, status and limitation subheadings. Long or
machine-formatted findings receive explicit snapshot-bound presentation points.
Full claims, analysis, results, corrections, limitations and all evidence stances
remain in native Evidence and reasoning disclosures in the initial HTML. Short
summaries do not replace or adjudicate the recorded scientific findings.

Complete retained report is removed from the page. Supporting record & provenance
retains work status, credit, version and original claim/scope; its duplicate
Complete evidence and counterevidence block is removed. The full-width download
is labelled Download report files (.zip). Reports remain in the ZIP and full
Copy for AI context. Independent scientific review remains pending.

## Published report cleanup

Current publication copies remove internal model/auxiliary-task narratives,
compiler and visual-check logs, conversation identifiers, host-file inventories,
blank hash sentences and pure operational command blocks. Scientific scope,
failed checks, counterevidence, quantitative results, equations, code examples,
source versions and citations remain. Mixed paragraphs use individually reviewed
replacements bound to their original paragraph hashes. Mathematical spans and
scientific code blocks are checked for preservation; pure hash displays are
identified separately from scientific equations.

Published ICML TeX renders transcribed Markdown headings as actual section
headings, presents supplied title metadata explicitly and omits empty metadata
lines. Missing public code filenames and source locators are restored only from
the retained source or existing verified identity, without restoring host paths
or internal task inventories. No date or source identifier is invented.

The maintainer authorized overwriting the current presentation files and their
artifact bindings. A private stopped-writer backup and the existing repository
history preserve predecessors. Original article PDFs and raw archives are
unchanged. This is a presentation correction, not a new scientific revision.

A new explicit reader library compiles changed maintained report sources with
Tectonic's untrusted-input mode. Exact previously accepted PDFs are reused only
when source and canonical record hashes match. Original article and published
revision members are copied solely from the accepted manifest. All selected
sources, outputs and compilation logs receive hash bindings outside the public
reader ZIP; no author programs or private uploads are discovered or executed.

## Acceptance and release

Check every case, structured problem, context and ZIP against its current
snapshot and catalogs. Verify concise summaries, title mappings, disclosure
content, full-width downloads, cleaned report text and exact original article
identity. Inspect representative long, mathematical and code-heavy PDF layouts
and both narrow and wide browser layouts. Run the project and isolated website
checks, package build and installed-wheel offline smoke.

Both the pull-request checks and the five checks at the final main head must pass
before deployment. The release procedure takes a fresh stopped-writer backup,
rehearses a restore on a separate copy and preserves all operational tables and
protected files. Canonical public acceptance and actual deployment evidence are
tracked in Issue #21; a prepared release alone does not establish completion.
