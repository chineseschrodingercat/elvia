Prepare your report before creating an account

One scientific report. A clear route to submit it.

Choose the template for your contribution, write in your usual scientific format and upload the finished PDF or LaTeX file. A focused check of one claim is enough. You do not need to retype every finding into a web form.

AI-assisted review is strongly encouraged. ChatGPT, Claude and Gemini can help you inspect arguments and organize your report. Verify the sources and reasoning, disclose the tools you actually used, and identify unverified suggestions. Fully manual reviews are equally welcome.

The templates and examples below are public. Registration is needed when you save or submit your own work.

The actual submission form shows only the template for your chosen route. Each file type has a separate upload slot. A report ZIP is not needed. Both template PDFs are three pages; your own report has no minimum page count.

What makes the report useful?

  1. Locate the claim. Give the exact paper version and page, equation, figure or source-code location. Briefly quote or faithfully paraphrase the passage.
  2. Show the check. State assumptions and units; include the derivation, counterexample, observation or reproducible calculation. Distinguish a proof from a finite check and a program you ran from code you only read.
  3. Bound the conclusion. Explain which result is affected, retain counterevidence, and list what remains unresolved. Use Minor, Major, Needs evidence or No issue found within scope, with a reason.
  4. Make the report self-contained. A single .tex file must include its references and equations without external image, \input or bibliography files. Use a self-contained PDF when those resources are essential.
  5. Declare assistance and responsibility. Describe actual AI models/settings/dates and your own checks when relevant. Include conflicts, your role and preferred attribution. Do not add private contact details.

For code, a short README with dependencies, commands and expected output is helpful; no prescribed folder structure is required. The website does not execute submitted code or compile uploaded LaTeX.

Before claiming a paper, read its availability indicator. One contributor reserves it at a time, through editorial review and integration. You can still read its public evidence while it is reserved.

Two filled examples, using one invented paper

These examples illustrate the report structure and a constructive revision. They are fictional teaching examples, excluded from research evidence. No real paper, researcher, review or adoption is represented.

Fictional teaching example: first paper and report

Paper identity and scope

Paper: Normalizing a detector signal, fictional teaching version 1. No DOI, venue or real authors. Source: the invented passage below is the entire source material for this exercise; no supplement or code exists.

Methods, Equation (1): “The normalized signal is r = x / x₀.”

Scope: inspect how the ratio responds to a multiplicative change of units when x₀ is nonzero. Noise, experimental measurements and zero-reference behavior are outside this first report.

Problem 1: State the shared scaling condition

Location and assessment: Methods, Equation (1); Minor, a local clarification of the conditions needed to interpret the formula.

Claim and assumptions: the passage defines a ratio without stating a units convention. Let x and x₀ have compatible units and let both be multiplied by the same nonzero conversion factor c.

r′ = (c x) / (c x₀) = x / x₀ = r.
For x = 6 and x₀ = 3, r = 2. Converting both by c = 10 gives 60 / 30 = 2; converting only x gives 60 / 3 = 20.

Evidence: the algebra establishes invariance under shared multiplicative scaling. The arithmetic illustrates it; neither is an experimental result. No code was run.

Impact and counterevidence: the ratio itself is valid under the stated conditions. A reader may already infer compatible units. The proposed clarification prevents a misuse; it does not show that an experiment or central conclusion is wrong.

Possible clarification: “Compute x / x₀ using the same multiplicative unit scale for numerator and reference.” This is a proposal for the teaching passage, not an adopted correction.

Limits: additive offsets, x₀ = 0, measurement noise and experimental validity have not been checked here.

Reproduction and declaration

Reproduction: the displayed identities are self-contained; verification code is not needed. Conclusion: a bounded units clarification is useful; the ratio formula remains intact.

Illustrative declaration: “AI used: No. This fictional exercise assumes a manual check of the stated algebra. No real contributor or independent reviewer is represented. No conflicts apply to this invented example.” For your real report, replace this with an accurate account of your own work and AI assistance, if any.

Fictional teaching example: review and revision

Published baseline and review scope

Paper: the same invented Normalizing a detector signal, teaching version 1. Baseline: fictional case teaching-normalization, revision 1: the first-report example immediately above. This is an in-page teaching reference, not a real Atlas record or public submission.

Question: retain the valid multiplicative-scaling argument while clarifying the limits of the term “same scale”; add a separate check of zero-reference behavior.

Response map: Existing Problem 1 — Agree with the algebra and Minor clarification; retain the finding and explicitly exclude additive offsets. New Problem N1 — add the nonzero-denominator condition.

Response to existing Problem 1: State the shared scaling condition

Earlier finding: shared nonzero multiplicative rescaling preserves x / x₀. Original location: the invented Methods, Equation (1).

Independent check in this exercise: cancel c from (c x) / (c x₀) when c and x₀ are nonzero. For contrast, adding 10 to both readings changes 6 / 3 = 2 to 16 / 13, approximately 1.231.

Result and counterevidence: the first report is correct within its multiplicative scope. The offset example does not refute that argument; it explains why the same statement cannot cover all changes of measurement convention.

Requested revision: retain Problem 1 as Minor and add: “A shared additive offset generally changes this ratio.” No claim about actual detector calibration is made.

New problem N1: A zero reference leaves the ratio undefined

Location and assessment: the same invented Equation (1); Minor, a missing domain condition in this teaching passage.

Check: at x = 6 and x₀ = 0, the real-valued expression 6 / 0 is undefined. The first report explicitly left zero-reference behavior outside its scope. No program execution or empirical observation is claimed.

Requested clarification: state x₀ ≠ 0 and define a separate handling rule if zero can occur. Counterevidence and limits: if a real measurement protocol already excludes zero, this would need only a cross-reference. This exercise establishes nothing about zero frequency or the choice of a handling rule.

Revision summary and declaration

Changes: retain the original algebra and outcome; clarify the offset boundary in Problem 1; add the domain condition under N1. Verification code: not needed for these displayed calculations. Publication boundary: this proposed revision is not a published correction, independent scientific decision or author adoption.

Illustrative declaration: “AI used: No. This fictional exercise assumes manual algebraic checks; no real reviewer or conflicts are represented.” Replace it with truthful provenance, role, conflicts, attribution and date for a real submission.
