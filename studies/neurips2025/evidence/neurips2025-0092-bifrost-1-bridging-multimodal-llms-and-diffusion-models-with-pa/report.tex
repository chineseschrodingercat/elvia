\section*{Problem 1: New generation modules are not initialized as parameter copies}

Source: Figure 2 and Section 3.2, PDF p.4; Appendix A, PDF p.17; submitted constructor and train\_fsdp.py

Assessment: supported; impact: minor

\subsection*{Source claim (paraphrase)}

Figure 2, Section 3.2 and Appendix A specify copies of pretrained attention, MLP and normalization parameters. The constructor instead creates new modules after loading the base model.

\subsection*{Analysis}

`add\_vision\_attention` creates new linear projections; analogous MLP/norm methods create new state, while copy operations appear only in comments. A loaded four-dimensional query projection with every weight \(2\) and bias \(1\) maps the first basis vector to \((3,3,3,3)\); a newly initialized projection does not read those values. The fresh training path has no intervening copy pass. Inference and resumed training can separately load learned generation weights, which is a critical countercontrol.

\subsection*{Finding and scope}

The fresh recipe does not implement the stated copy initialization. It does not show that inference uses random generation weights or that original checkpoints began incorrectly.

\subsection*{Proposed correction}

Create independent copies of the intended loaded modules before optimizer creation, preserving equal initial values and distinct storage. Do not overwrite an explicitly loaded trained generation checkpoint with a fresh copy.

An explicit local correction is described; author adoption and a corresponding published erratum are not established.
