\section*{Problem 1: Consistency loss is undefined on allowed real query features}

Source: Section 3.4, Eqs.(7)–(9), PDF p.6; xmuda/train\_dg\_clip\_XDiff3D.py, line 241

Assessment: supported; impact: major

\subsection*{Source claim (paraphrase)}

Low-rank real query matrices are inserted directly into a KL-like logarithmic ratio against an MLP containing a linear layer and layer normalization. The release also passes raw queries to kl\_div and reduces a scalar along dimension one.

\subsection*{Analysis}

Take rank-one queries \(Q=(1,-1),Q^{\prime}=(1,1)\), with rank-one reconstruction, identity linear map and default unit/zero layer-normalization affine parameters. The transformed denominator is \((a,-a)\), \(a=(1+\varepsilon)^{-1/2}>0\), so the second log ratio is \(\log(-1/a)\), not a real number. SVD truncation and layer normalization do not enforce positivity or probability normalization. Independently, even valid log-probability/probability arguments to default kl\_div produce a scalar, so the subsequent sum over dimension one is invalid.

\subsection*{Finding and scope}

The central consistency objective is not mathematically defined throughout its stated feature domain, and the enabled release loss has an additional reduction failure. This does not independently disprove reported mIoU values or identify the historical working implementation.

\subsection*{Proposed correction}

Define a probability axis and temperature, apply softmax/log\_softmax to the query logits, then sum an unreduced KL along that probability axis and average the intended remaining dimensions. This changes and clarifies the mathematical objective.

The described correction remains a proposal; author adoption or a corresponding erratum is not established.

\section*{Problem 2: Extraction and evaluation contracts do not match the described paths}

Source: Experimental inference description, PDF p.7; xmuda/XDiff3D/UniDSeg/xmuda\_arch.py; xmuda/data/utils/validate.py

Assessment: supported; impact: minor

\subsection*{Source claim (paraphrase)}

The release’s default diffusion extractor returns no query pair, and its three-dimensional wrapper requires a two-dimensional query argument that validation omits, despite the paper’s three-dimensional-only inference description.

\subsection*{Analysis}

The extractor returns queries only under its nondefault hook branch, while the default wrapper unpacks its return. Separately, Net3DSeg.forward requires data\_batch and object\_query\_2D and uses the latter unconditionally; validation calls model\_3d(data\_batch). The missing argument fails at Python binding before input data, hardware or learned weights can affect it. eval mode does not change the required function signature.

\subsection*{Finding and scope}

The current release does not implement a working path with these declared interfaces. It remains possible that another implementation generated the reported results; no complete substitute architecture is invented.
