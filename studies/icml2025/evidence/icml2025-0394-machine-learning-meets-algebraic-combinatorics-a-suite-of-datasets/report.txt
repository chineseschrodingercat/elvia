Abstract: All nine dataset descriptions, the complete appendix and relevant supplied source files were examined. The released lattice-path generator sorts Lagrange groups by path data instead of their numerical invariant. Independently, the reported RSK mean baseline is incompatible with the stated full-permutation, binary-inversion, standard-MSE protocol. These are Major issues within their respective components, with historical code correspondence unresolved. Local metric and definition discrepancies and disclosed selection on the test set are also documented. This does not establish that the whole repository is unusable. Adjudication remains pending.

# The released lattice-path ordering

Problem 1 (The sort key selects complete tuple fields, not a nested numerical entry).  In , cell 14, the code sorts `D_l.items()` using `operator.itemgetter(1,0,-1)`. Each item is \(((D,q),[(p,L(p)),\ldots])\). The key is therefore the tuple consisting of the whole path list, the \((D,q)\) key, and the whole path list again. It is not the nested Lagrange number. Cell 13 then creates covers between adjacent groups in that incorrectly sorted list. This contradicts the numerical ordering required by Appendix C.2.5, p. 37.

The distinction is material: lists of \((p,L(p))\) compare first by the binary path \(p\). An independent enumeration of the 4,862 valid paths to \((10,9)\) supplies a finite witness. Encode east by 1 and north by 0, and set \[\begin{aligned}
 p&=1101010101011001100,\\
 q&=1101010101011010010.\end{aligned}\] Both remain strictly below \(y=x\) at intermediate integer points and hence below the endpoint diagonal \(y=9x/10\). Each lies in a singleton \((D,q)\) group in the independent enumeration. They satisfy \(p<q\) lexicographically, but \[\begin{aligned}
 L(p)^2&=24668154583661/2459580573025,\\
 L(q)^2&=499765652882717/55353495840049,\end{aligned}\] so \(L(p)\approx3.16692518>L(q)\approx3.00476613\). Singleton groups make this relative-order reversal independent of the enumeration order of paths within a group.

The calculation uses an independently written exact continued-fraction computation: prepend 2 to the sequence that replaces equal adjacent path bits by \((1,1)\) and unequal bits by \((2)\); for every cyclic rotation multiply matrices \(\left(\begin{smallmatrix}c&1\\1&0\end{smallmatrix}\right)\). If the product is \(\left(\begin{smallmatrix}a&b\\c&d\end{smallmatrix}\right)\), compare the rational values \(((a-d)^2+4bc)/c^2\) and take their maximum. Fractions are compared exactly; decimal values above are illustrative. This checks the invariant specified in the supplied generator, not a new theorem identifying it with all external number-theoretic conventions.

Impact and counterevidence. This is a Major release-code defect in a core label-generation step. The argument proves the constructed group order is wrong; it does not assert that this particular pair survives every later filtering step or appears in the historical train/test files. A corrected historical notebook could explain valid published data. Such a notebook, data hashes and exact label audits are needed to resolve that possibility.

Repair. Sort groups by their actual numerical invariant, preferably using exact \(D/q^2\) comparisons, coalesce equal invariant values, then reconstruct covers and verify that each satisfies strict increase and no intermediate level. The source also drops all pairs beginning at a path having any common cover (cells 17–20), whereas the prose describes removing only pairs common to both orders. That population difference must be documented or repaired separately. The finite witness verifies the ordering defect; complete label regeneration and downstream retraining were not performed.

# Metric consistency

Problem 2 (The stated RSK mean baseline cannot have MSE 0.21).  Appendix B.5 (p. 19) defines binary inversion-vector targets; Appendix C.2.3 (p. 34) says all permutations are included. Table 3 (p. 14) reports MSE 0.21 for the predictor that always guesses the training-label mean, for both \(n=8\) and \(n=9\). These statements are incompatible under ordinary coordinate-averaged MSE on a disjoint train/test partition of all permutations.

Equation reference: eq:mse. For every inversion coordinate \(Y_{ij}=\mathbf1\{w_i>w_j\}\), exactly half of all permutations have value 1: exchanging the values at positions \(i,j\) is a fixed-point-free pairing that reverses the comparison. Let \(a\in(0,1)\) be the training fraction, \(p\) its mean on this coordinate and \(q\) the test mean. Exhaustive, disjoint coverage gives \[ap+(1-a)q=\tfrac12.\] The mean predictor’s test error on this coordinate is consequently \[
 q(1-p)^2+(1-q)p^2
 =\frac14+\frac{1+a}{1-a}\left(p-\frac12\right)^2\ge\frac14.\] Averaging coordinates preserves the bound. No assumption of random splitting or large sample size is needed. The current loader, lines 469–481, constructs all pairwise inversion bits, and the RSK generation notebook partitions all permutations using the same shuffled indices for tableaux and targets. It corroborates the stated setup but does not establish the historical implementation. Independent rational checks verify ([eq:mse] (#eq:mse)).

Impact and repair. The discrepancy is Major for the RSK evaluation component: at least the target encoding, dataset coverage, baseline definition, MSE reduction or printed score must differ from the stated protocol. An unstated rescaling or filtering could explain 0.21, but would itself require a corrected specification and rechecked comparisons. This is not evidence of fabricated data, nor proof that the trained models generalize well. Release the exact evaluation transformation and baseline outputs, then recompute or correct Table 3. Section 4.5 also calls the target a descent-set vector, unlike the appendix and code. A descent set is not an injective permutation representation; for example 132 and 231 both have descent set \(\{2\}\). Merely replacing the word “inversion” by “descent” does not explain 0.21 either, since every adjacent-comparison bit is also balanced over all permutations.

Problem 3 (The majority baseline in the macro-F1 table is an accuracy).  Table 5 (p. 14) labels its values macro F1 but repeats Table 4’s majority-class accuracy column. For the \(n=5\), \(q^2\) task, Table 13 gives test counts \((2876,4)\). Always predicting zero has accuracy \(2876/2880\approx99.8611\%\), but macro F1 \[\frac12\left(\frac{2\cdot2876}{2\cdot2876+4}+0\right)
 =\frac{2876}{5756}\approx49.9653\%,\] not 99.9%.

Both true classes occur, so undefined absent-class conventions do not resolve the discrepancy. This Minor table error changes the apparent comparator: the reported 50.0% MLP macro F1 is consistent with majority-only prediction, rather than far worse than a 99.9% macro-F1 baseline. The model’s own F1 values were not reconstructed. Recompute every baseline with the same label set and averaging rule as the models, or explicitly label a separate accuracy column. The independent arithmetic verifies this correction for the stated row.

# Dataset definitions and evaluation selection

Problem 4 (mHeight uses incompatible extrema, label offsets and domain descriptions).  Section 4.2 (p. 5) defines the minimum of \(a_i-a_\ell\) over all 3412 patterns. Figure 6 (p. 17) instead displays \(\max(3-2,4-2,3-1)=2\) for 34512; the defined minimum is 1. The p. 17 text’s permutation \((6,8,7,5,4,9,3,0,1,2)\) is labeled 1, whereas direct enumeration gives minimum height 2.

In the current mHeight generation notebook, cell 2 takes the minimum, excludes permutations containing 4231, and writes `m-1`. Thus a label of zero is a shifted positive height, not the literal height defined in the prose. Independent enumeration of all \(8!=40320\) permutations, keeping those with a 3412 pattern and no 4231 pattern, produces shifted-height counts \[(8388,644,96,12,1).\] These equal the combined training and testing counts in Table 7 exactly. This corroborates the shifted, restricted interpretation without running author code or reading all historical data. The README repeats the unshifted definition and does not resolve the issue. Classification accuracy is invariant under a consistent one-to-one label shift, so this is assessed as Minor; it is not a demonstrated collapse in predictive accuracy. State the 4231 restriction, label-to-height map and treatment of pattern-avoiding permutations, and correct Figure 6. Claims covering all permutations with 3412 need to be narrowed or supplied with new data.

Problem 5 (Selection and reported evaluation reuse the test set).  Appendix B.10 (p. 27) says the best test score was recorded across 60 epochs and describes hyperparameter optimization. Appendix B.11 (p. 29) expressly chooses the best of 100 generated programs by evaluating each on the test set. These test values are selection criteria, not independent assessments of the selected solution. The current also returns the test dataset from both validation loaders.

For an explicit illustration, let 100 independent candidate classifiers each have true accuracy \(1/2\), and let their test counts be independent \(\operatorname{Binomial}(20,1/2)\). The expected maximum test accuracy is \[\frac1{20}\sum_{k=1}^{20}\left[1-\Pr\{\operatorname{Binomial}(20,1/2)<k\}^{100}\right]
 \approx0.773197.\] This is a finite demonstration of selection optimism, not an estimate of this paper’s inflation; its candidates and errors need not be independent. Three initialization repeats do not turn a previously used selection set into an untouched test set.

The paper openly frames these as exploratory diagnostics and says performance alone does not establish a useful conjecture (p. 2). That is meaningful counterevidence against treating the numbers as a claimed definitive leaderboard. Accordingly the finding is Minor in this framing: label the scores as best-on-selection-set diagnostics and restrict the relative-difficulty interpretation, or introduce a separate validation set and assess selected models/programs once on an untouched test set. No such rerun was performed.

# Other checks, alternative explanations and remaining coverage

The Schubert parity shortcut is disclosed on p. 8 and in Table 6, so the 100% examples are not presented there as new mathematical discoveries. The printed parity direction is nevertheless reversed: homogeneity gives \(\ell(\gamma)=\ell(\alpha)+\ell(\beta)\) for a nonzero structure constant, hence the sum of the three lengths is even, not nonzero modulo 2. The later generation notebook samples a geometric number of transpositions and checks absence from the product support, consistent with the described attempt to break the original one-transposition shortcut. It does not establish elimination of every degree or sampling shortcut. Versioned old/new data and rerun scores are needed for that claim.

The supplied README discloses a January 2026 fix to differing representations of weaving positives and negatives, which had caused artificially high accuracy. This is source evidence of an acknowledged release issue; without old/new payloads or corrected experiment logs its numerical effect on Table 1 cannot be reconstructed. The present weaving generator was only read statically. The current Grassmannian notebook has exploratory settings different from the paper and does not prove that random negatives are all non-cluster variables; the datasheet itself qualifies positive coverage as probabilistic. No new false-negative rate is asserted here.

The lattice path length to \((n,n-1)\) is \(2n-1\), and the endpoint diagonal has slope \((n-1)/n\). Appendix B.7 instead prints \(2n+1\) and \(n/(n-1)\), apparently mixing conventions. The source’s strict prefix excess of east over north is compatible with the intended adjacent endpoint pair. Quiver mutation generation uses a depth-limited class call; the datasheet’s separate description as nine random mutations is not a complete account of that code. Several table counts require source-data reconciliation, including the duplicated constant-term and \(q^4\) KL distributions. These observations are not silently promoted into claims that all affected labels are wrong.
