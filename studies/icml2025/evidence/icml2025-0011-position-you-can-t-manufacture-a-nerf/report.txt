# Problem 1. Released sampling differs from the written protocol

Source claim and location: section 4.1, p.8, defines high curvature at an adjacent-normal angle exceeding 0.3 rad, specifies a neighborhood width t=0.035 times the minimum bounding-box dimension, allocates at least 25% of the samples near qualifying edges, and ultimately selects 10,000 points. The earlier paragraph also states a minimum of ten samples per edge. Evidence E1 and E2.

Static check: sample_mesh.py line 75 uses np.deg2rad(2.5); line 89 applies that threshold. Lines 104-112 interpolate on the edge at spacing 0.001. Line 153 requests 150,000 surface points; line 158 concatenates edge and surface samples; lines 177-181 shuffle and save the combined array. This file contains no implementation of the stated distance zone, allocation guarantee, or final 10,000-point selection. The two angular thresholds are 0.0436332313 and 0.3 rad, differing by a factor of 6.87549354.

Complete analytic witness: consider the convex regular 64-gonal prism with vertices (0.5 cos(2 pi j/64), 0.5 sin(2 pi j/64), +/-0.5), j=0,...,63. It has 66 planar BREP faces and is therefore complex under the paper’s face-count criterion. Its closed convex boundary has no self-intersections, every edge has exactly two incident faces, and vertex links are single cycles. All vertices have norm sqrt(1/2), so the whole convex prism lies inside the unit sphere. Triangulate each planar face without altering its surface. Along each vertical prism edge, adjacent outward normals differ by 2 pi/64.

\[0.0436332313 < \theta = 2\pi/64 = 0.0981747704 < 0.3.\] The released threshold selects those vertical edges; the written threshold does not. This verifies a difference on an input satisfying the stated geometry assumptions. It does not predict a published table entry. In particular, no trained model or author sampler was executed.

Alternative reading and impact: this release could be an intermediate preparation script followed by unpublished sampling or experiment-specific code. A later subsampling step could reconcile the point count. The inspected release does not identify that step or connect any commit to the reported tables. The supported defect is a local reproducibility/method discrepancy (Minor); changes to model performance remain Needs Evidence. A threshold-only edit is not a verified repair because the other protocol differences remain. Resolution requires an experiment-producing revision/configuration and matched runs if numerical impact is to be established.

# Problem 2. Dimensional interpretation of Chamfer error is under-specified

Source claim and location: Table 1 and section 2.1, p.5, compare normalized Chamfer values with the absolute tolerances on p.3 and in Appendix Table 5, using a four-inch object as an illustration. The metric equation, power of distance, bidirectional aggregation, and per-object inverse scale are not given. The adjacent prose refers to a median, while Table 1 explicitly reports averages and standard deviations. No released evaluation script resolves these choices. Evidence E1-E2.

Check: for the following explicitly defined illustrative family, scaling follows directly by factoring the norm in every nearest-neighbor term. Here r>0 is the power, a>0 is a uniform scale, and P,Q are nonempty finite point sets.

\[D_r(P,Q)=\frac{1}{|P|}\sum_{p\in P}\min_{q\in Q}\|p-q\|^r+\frac{1}{|Q|}\sum_{q\in Q}\min_{p\in P}\|q-p\|^r,\qquad D_r(aP,aQ)=a^rD_r(P,Q).\] Linear conversion is valid for r=1; r=2 has squared-length units until an appropriate square root is taken. Fitting inside a unit sphere does not, by itself, specify the object’s normalized longest dimension. An average nearest-neighbor value also cannot certify a worst-case tolerance bound or identify the failing manufacturing feature.

Counterevidence: if the actual statistic is an unsquared distance and the normalized longest extent is 2, scaling to four inches gives a=2. Then 0.029 becomes 0.058 inches, 11.6 times 0.005 inches. Thus a plausible interpretation supports the stated order-of-magnitude comparison; this audit does not demonstrate a wrong numerical conversion. Judgment: Needs Evidence. Supply the metric equation, dimensional inverse transforms, exact summary statistic, and feature-appropriate deviation measures. No correction to the table or experimental result is proposed.

# Problem 3. Thang3D percentage needs an explicit denominator

Source claim and location: section 1.4, p.4, describes 200 downloaded Thang3D models; Table 2, p.6, reports 6.9% manifold for Point2CAD. If there is one binary result for each of exactly 200 objects, every percentage is k/2 percent for integer k. Thirteen successes give 6.5%; fourteen give 7.0%; rounding to one decimal cannot give 6.9%. This is an exact finite arithmetic check.

Alternative readings include an evaluated subset after exclusions, multiple bodies per model, or an average over runs. Any could change the denominator or aggregation. The table does not specify which applies. Judgment: Needs Evidence, with bounded reporting impact. The calculation does not establish a false count or a changed comparative conclusion. Resolution requires the evaluated numerator, denominator, exclusions and averaging rule; it does not justify substituting 7.0%.

# Dependence, scope clarification and later material

The finite 256-cubed reconstruction experiment supports a statement about the evaluated pipeline and datasets. It does not establish a representation-wide impossibility for every triangulated shape and tolerance. An independent illustration is an exact triangulation of a convex 16-gonal prism of radius 2 inches and height 1 inch: it has 18 BREP faces, 32 vertices, 60 triangles, 90 mesh edges, Euler characteristic 2, two triangles per edge, and cyclic vertex links. Each triangle lies in and partitions an original planar face, so nominal representation error is exactly zero. This is a scope clarification, not a learned-model or machining reproduction; it does not refute the measured failures or guarantee tool-path feasibility for arbitrary shapes.

The paper discusses alternative manufacturing views in section 5 and distinguishes mechanical validity from geometric validity. These counterweights matter when reading its broad statements. No central conclusion is downgraded solely because a future pipeline might perform better. The released repository’s inspected history, issues and releases did not reveal a correction; exact-title searches found no separate later manuscript or erratum. OpenReview revision contents were not accessible, so this is a bounded search result, not a claim of exhaustive absence.
