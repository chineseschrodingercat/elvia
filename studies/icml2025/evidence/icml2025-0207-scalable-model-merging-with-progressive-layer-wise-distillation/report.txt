Abstract: The two hardness theorems, progressive dual-input distillation, experimental comparisons and frozen released sources were inspected. Both hardness constructions are valid within their stated hypothesis classes and unbounded-data settings. The release contains a wrong-task teacher-prefix selection, inconsistent save/cleanup paths, and incomplete exclusion of NLG calibration prompts. These are demonstrated source-level defects, while their effect on historical paper results remains unverified. The headline vision/NLU arithmetic is consistent. NLG cohort comparability and the claimed feature-versus-logit comparison need further evidence. The supported overall assessment is Minor; adjudication remains pending.

# Independent verification of the central mathematics

## Fixed-model hardness

Theorem 3.1, pp. 3 and 15, is valid for the constructed linear-regression task. Given a deterministic merged weight \(\widehat w\), choose an expert \(w_i\ne\widehat w\); distinct experts ensure one exists. With \(\delta=\widehat w-w_i\), take \[x_i=\frac{2\sqrt C}{\|\delta\|^2}\delta,\qquad y_i=x_i^\top w_i.\] The expert has zero loss and the merged residual is \(2\sqrt C\). Choose the other input noncollinear with \(x_i\) in dimension at least two and label it by its expert. Both equations can be interpolated by a common weight. Therefore the averaged half-squared loss of the merged model is at least \(C\), while both experts and a joint model have zero relevant loss. Relabeling which expert is attacked does not require the merging rule to be permutation invariant.

## Learned-model hardness

Theorem 3.2, p. 16, explicitly restricts the linear hypothesis class to \(w\ne0\), uses loss \(\max\{-y(w^\top x+b),0\}\), and learns a normalized maximum-margin separator. The two original task pairs on the coordinate axes give experts \(e_1,e_2\). For any nonzero merged direction, an unbounded positive point \((p,q)\) can have merged score below \(-5C\) while \(p>1\) or \(q>1\). Appending it to the corresponding task leaves that expert’s maximum-margin solution unchanged: its original opposite pair already caps the normalized margin at one.

The union remains separable. If \(p>1\), a vector \((1,\eta)\) with sufficiently small \(\eta>0\) separates all five points; the other case is symmetric. As an independent exact check, for merged weight \((1/2,1/2)\), \(C=1\), and new positive point \((2,-14)\), the five merged margins are \[(1/2,1/2,1/2,1/2,-6),\qquad \text{mean loss}=6/5>1.\] The union separator \((1,1/10)\) has margins \((1,1,1/10,1/10,3/5)\), all positive. Strict inequalities permit arbitrarily many nearby damaging points, supporting Remark A.1’s low-accuracy construction.

The nonzero-weight restriction matters: the identically zero predictor would have zero stated margin loss, but is explicitly excluded. These results are worst-case impossibility statements with unbounded inputs/loss, not proofs that each practical task needs data or that a particular few-shot sample size suffices. Remark 3.3 acknowledges the worst-case scope.

## Progressive objective and scope

Algorithm 1 correctly maintains a merged prefix and each expert’s own prefix. It is presented as a surrogate, with empirical comparison to global distillation; no theorem guarantees a global minimizer of the nonconvex objective. If all preceding layer discrepancies vanish, the input paths coincide inductively. Zero discrepancy at a single isolated layer is not enough.

The sum over \(j\) in printed Equations (1)–(2) incorrectly repeats \(\lambda_i\circ\tau_i\); Algorithm 1 and the inspected parameter-merging code correctly use \(\sum_j\lambda_j\circ\tau_j\). This is a local index correction, with direct counterevidence against treating it as the implemented method.

Elementwise scaling increases flexibility relative to scalar coefficients. If every coordinate has a nonzero task-vector entry, it can already reach the full parameter space; the reported prior then acts through initialization/optimization rather than a strict hypothesis-class restriction. This does not refute an empirical advantage.

# Verified release-level Problems

Problem 1 (NLU teacher prefixes are selected from the wrong task).  The released NLU initialization repeatedly loads the final task’s prefix, rather than each teacher’s own prefix required by Algorithm 1.

In `NLU/main_prodistill.py`, lines 70–71, the loop variable is `dataset`, but the call is `load_fine_tuned_model(args, dataset_name)`. The documented top-level setup leaves the global `dataset_name` equal to `rte`. Thus all eight extractors are built from RTE. The helper in `NLU/model_merging_methods/distill_merging_utils.py` selects `args.load_model_paths_dict[dataset_name]` and captures inputs to the first encoder layer. Subsequent layer loading correctly selects each individual task.

If \(E_i\) is task \(i\)’s embedding prefix and \(B_i\) its first block, the target should be \(B_i(E_i(x))\), but the release uses \(B_i(E_{\rm RTE}(x))\). These expressions need not agree. An independent scalar illustration with \(x=1\), \(E_i(x)=2\), \(E_{\rm RTE}(x)=3\), and \(B_i(z)=5z\) gives 10 versus 15. This is a logical illustration, not a BERT checkpoint measurement.

Assessment: Minor for the released implementation. The defect changes the intended teacher stream when prefixes differ. Identical prefixes on the calibration inputs would neutralize it, and the historical experiment revision and actual feature differences are unavailable. No corrected benchmark score or historical failure is inferred. The local repair is to load the current `dataset` and regenerate the cached features. Full training after that repair was not performed.

Problem 2 (Documented entrypoints do not complete their own file lifecycle).  The released Vision and NLU paths contain independently verifiable execution blockers.

The Vision script constructs a layer directory including the model name, then creates and reloads \[\texttt{layer\_save/ViT-B-32/100/0.01/64/}.\] Its save expression omits the separator between `args.layer_save` and `args.epochs`, producing instead \[\texttt{layer\_save/ViT-B-32100/0.01/64/layer\_0.pt}.\] The ordinary fresh run therefore lacks the save parent; even externally creating it would not align the subsequent reload path. This follows from the actual defaults, README invocation, directory creation and save/load expressions, without executing author code.

Separately, `NLU/main_prodistill.py`, line 139, evaluates `args.tag` in its cleanup path although the complete parser defines no `–tag` and the setup does not assign it. The ordinary entrypoint therefore raises an attribute error at that point before returning to evaluation. Its saved layer directory also lacks the extra tag component.

Assessment: Minor for reproducibility of this snapshot. Use one common path builder for create/save/read/cleanup, and remove the undefined extra component. These local consistency repairs are verified as path corrections, not as a successful neural training run. An unpublished corrected entrypoint could have produced the historical tables; these release defects do not establish otherwise.

Problem 3 (NLG generation does not consistently exclude calibration prompts).  The documented release path violates the paper’s stated exclusion rule for instruction evaluation and does not reliably implement it for MBPP.

Appendix B.3, p. 18, explicitly samples NLG adaptation data from test sets and excludes those samples during evaluation. The loader `NLG/utils/llm_data_loader.py`, lines 57–60, uses a seed-zero permutation, assigns its first `val_shot` indices to calibration and the remainder to evaluation. The merge script saves those remainder indices.

However, `NLG/eval_instruct.py`, lines 64–78 and 119, loads the same complete Alpaca JSON and generates every instruction using the default full range. It never consumes `instruct_indices.pt`. The complete `NLG/merge_gen.py` simply concatenates the generated batches. The README then sends this combined file directly to the Alpaca evaluator. Hence the documented path retains adaptation prompts in the evaluation-output file whenever instruction adaptation used a nonempty subset of that file.

In `NLG/eval_code.py`, lines 173–179, MBPP filtering removes items from `task_ids` while iterating over that list. For IDs \([11,12,13]\), with only 13 allowed, deleting 11 shifts 12 to index zero; the iterator next visits index one, now 13, leaving excluded 12 behind. This complete iterator-state counterexample proves the filter is not generally correct. It does not assert which actual saved MBPP indices occurred in the paper. Broad fallback on missing index files additionally evaluates all examples.

Assessment: Minor for the released evaluation protocol. Use the saved remainder IDs consistently, construct a fresh filtered list, assert empty intersection with calibration IDs, and fail explicitly when required index files are missing. The calibration procedure consumes inputs, not supervised answer labels; inclusion still violates the stated holdout protocol, but does not prove answer memorization or a measured score increase. Historical generation files, actual IDs and scorer runs are missing, so the published-score impact remains Needs Evidence.

# Empirical conclusions and unresolved support

The headline gains are arithmetically correct: \[86.04-79.90=6.14\text{ percentage points},\qquad
 0.7641-0.6980=0.0661.\] Tables 1–2 support the average vision and RoBERTa comparison, with visible task-level exceptions. Appendix D.3 reports three-seed analyses and acknowledges greater NLU variability with very few samples. Figure 5 also contains a small counterexample to universal progressive superiority: at 32-shot RoBERTa, DistillMerge scores 0.7490 versus ProDistill 0.7473. The broader claim is an overall empirical comparison, not a theorem of per-setting dominance.

NLG cohort comparability: Needs Evidence. Tables 3, 9 and 10 import TIES/WIDEN scores directly from another study, while B.3 evaluates a calibration-excluded remainder. No common sample-ID and denominator binding is supplied. The raw Code+Math gap is \(0.2806-0.2723=0.0083\); the effect of different cohorts cannot be determined without per-example outcomes. In Table 9, ProDistill’s 64-shot raw average 0.2944 is lower than WIDEN’s 0.2968, while its normalized average is higher. Metric and cohort qualification are essential; no corrected ranking is inferred.

Feature versus logit supervision: Needs Evidence. Page 5 attributes this comparison to C.3, but C.3 compares hard-label cross-entropy with teacher-feature matching, not soft teacher-logit distillation. The displayed evidence supports the narrower hard-label comparison. It does not establish that the claimed feature/logit ordering is false.

Resource scope. Section 6.3 expressly excludes preprocessing and evaluation from measured training GPU memory. Layer updates avoid keeping all layers’ optimizer states, but total model storage, loading, cached data and end-to-end cost need separate accounting. The release loads whole checkpoints during some setup operations. The reported depth-independent layer working set is not an end-to-end memory guarantee. Epoch convergence does not by itself certify wall-clock savings. C.2 states equal computational budget, but the exact operational budget and raw profiles are unavailable.

The selected generated examples are final-answer illustrations, not correctness proofs for all intermediate reasoning. No model output, code generation or paid evaluator was executed in this review.
