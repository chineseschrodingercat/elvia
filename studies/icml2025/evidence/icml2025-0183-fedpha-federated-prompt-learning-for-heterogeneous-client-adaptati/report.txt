Abstract: The central projection has incompatible definitions in the paper’s equation, published pseudocode and pinned release. At the explicitly tested ratio \(\rho=1\), the equation selects a zero-dimensional subspace while Algorithm 1 returns the identity, which cannot project a nonzero global prompt onto its null space. The release instead retains reduced-SVD row directions. This demonstrated core construction error is Major; empirical accuracy failure is not established. Two further release-scoped discrepancies concern shifted EOS pooling and decomposition frequency. The reviewed aggregation and selected arithmetic checks found no issue within their stated scope.

# Method and central dependency

FedPHA uses a global prompt with fixed length \(T_g\) and personalized local prompts with client-dependent lengths \(T_i\) in a frozen CLIP backbone. Only global prompts are aggregated; local prompts remain personalized. The central interaction projects local prompts with \(Q=V_2V_2^\top\), obtained from the global prompt’s SVD. A pull loss brings local features toward projected-local features, while a margin-based push loss separates local and global features. Both classification losses and regularizers enter Eq. (13). The definition of \(Q\) therefore determines a training target central to the proposed method.

# Problem 1: incompatible projection operators and a failed null-space claim

Rating: Major. Locations: Figure 2, p. 4; Section 3.3, p. 5, Eqs. (8)–(10); Algorithm 1, p. 6; Table 8, p. 16; `trainers/GL_SVDMSE.py:129–165` and `trainers/GL_SVDMSE_HE.py:131–169`.

## The three constructions

The paper specifies a global prompt \(P_g\in\mathbb R^{T_g\times d}\) and a full SVD \(P_g=USV^\top\) with \(V\in\mathbb R^{d\times d}\). It selects the last \[d'=\lfloor(1-\rho)d\rfloor\] columns as \(V_2\). Algorithm 1 instead takes the slice \(V[:,d(1-\rho):d]\), retaining approximately \(\rho d\) columns. The release calls `torch.svd(global_ctx)` with its default reduced SVD, then uses `cutoff=int(S.shape[0]*(1-ratio))` and `V[:,cutoff:]`. Thus it counts from \(\min(T_g,d)\) singular directions, not from \(d\) full-SVD directions.

The locally installed primary PyTorch documentation explicitly states `some=True` by default and \(\min(m,n)\) columns in \(V\). Its exact excerpt and hash were read and preserved by the parent. The auxiliary agent also ran a small installed-library shape diagnostic using PyTorch 2.9.0+cu128, with no author import. This checks available-library behavior; it is not asserted to identify the historical training environment.

## A complete legal matrix witness

Use standard dimensions \(T_g=16\), \(d=512\) and \[P=[\operatorname{diag}(16,15,\ldots,1)\mid0_{16\times496}].\] This is an allowed real global prompt, with rank 16 and nullity 496. Its nonzero singular values are distinct; \(V=I_{512}\) is a valid full right basis and the reduced basis is \((e_1,\ldots,e_{16})\).

At the default \(\rho=4/5\):

- Eq. (9) selects the last 102 full-basis columns; \(Q\) has rank 102 and \(PQ=0\).

- Algorithm 1 starts at index 102 under floor indexing and keeps 410 columns, also with \(PQ=0\) on this example. A ceiling convention changes this count to 409, not to 102.

- The release cuts the 16 reduced directions at index 3 and keeps \(e_4,\ldots,e_{16}\). Its rank-13 projector lies in the global row space and \[\|PQ_{\rm release}\|_F^2=1^2+\cdots+13^2=819,
 \quad \|PQ_{\rm release}\|_F\approx28.618176.\]

A local prompt row \(p=e_{16}^{\top}\) is preserved by the released projector and annihilated by both full-basis alternatives. It can be repeated to any legal local prompt length.

At \(\rho=1\), explicitly tested in Table 8, rounding ambiguity disappears: \[Q_{\rm equation}=0,\qquad Q_{\rm Algorithm\,1}=I_{512},\qquad
 Q_{\rm release}=\text{projector onto the row space of }P.\] The latter two give \(PQ=P\ne0\), with \(\|P\|_F=\sqrt{1496}\approx38.678159\). More generally, Algorithm 1 returns the identity for every nonzero \(P\) at this setting; its range cannot lie in \(\ker P\). The equation and pseudocode thus prescribe opposite operations at a legal evaluated parameter.

These identities were checked analytically and with independent reviewer calculations. The parent recomputed all ranks, squared norms and boundary cases; no learned-prompt distribution or benchmark execution is needed to refute the general construction claim.

## Counterevidence and bounded significance

Section 3.3 also discusses retaining smaller singular-value components, which might motivate an approximate low-energy spectral filter. The released operator is a valid orthogonal projector onto such a reduced subspace; it is not undefined. This interpretation nevertheless does not reconcile the full-\(d\) equation, complementary slice and reduced-\(T_g\) cutoff. At \(\rho=1\), the published full-basis algorithm removes no global directions at all.

The finding is Major because a principal method component and the target of the pull loss are not mathematically defined consistently. A score decrease, whole-paper collapse or difficult repair is not required for that conclusion. The witness is a lawful prompt matrix, not a claim that training reached it. Which operator produced Tables 1–8 and whether their accuracy values remain valid require historical configurations and outputs.

## Local correction and unverified repair scope

If an exact null-space projector is intended, let \(V_r\) contain right singular vectors for nonzero singular values. Then \[Q_{\rm null}=I_d-V_rV_r^\top,\quad
 Q_{\rm null}^2=Q_{\rm null}=Q_{\rm null}^\top,\quad
 PQ_{\rm null}=0.\] This fixes the linear-algebra property. It does not preserve an arbitrary selected null-subspace dimension or settle differentiation/rank-tolerance choices and empirical behavior. If an approximate row-space filter is intended, it should instead be named and specified consistently with its \(\rho\) semantics. Merely requesting a full SVD is insufficient while the cutoffs disagree. No corrected FedPHA model was trained or certified.

# Problem 2: heterogeneous sequence pooling uses a stale EOS index

Rating: Minor, pinned-release scope. Locations: ; heterogeneous sequence construction, p. 5, Eq. (7).

Token IDs are created using the maximum prompt length \(T_{\max}\) and retained. The text encoder pools at `tokenized_prompts.argmax`, the EOS position in that maximum-length tokenization. The embedded sequence, however, concatenates the common prefix, a shorter learned context, and the shared suffix. EOS moves earlier by \(T_{\max}-T_i\), and zero-padding is appended only at the end. The pooling IDs are not adjusted.

For a class name with one token and a punctuation token, \(T_{\max}=32\) gives fixed zero-based pooling index 35. A length-four context has actual EOS at index 7; a length-16 context at index 19. Both are still pooled at index 35. Only length 32 has matching EOS and pooling positions. Other class-token lengths change the absolute indices but not the displacement.

This is a deterministic sequence-bookkeeping discrepancy, independently reconstructed without executing CLIP. A later padding-position hidden state may still attend to preceding content, so it is not evidence of an empty representation or a measured accuracy loss. A deliberate shared readout position is another possible design, but it would need a consistent description rather than mismatched token and embedding sequences. Historical experimental impact remains Needs Evidence. Updating each pooling index consistently is a local implementation correction, not a validated method repair.

# Problem 3: the release recomputes SVD per forward call

Rating: Minor, source/documentation discrepancy. Locations: p. 8, Table 3 and cost paragraph; both released trainers’ prompt-learner and model-forward paths.

The paper reports decomposition 4.2 ms, projection 2.8 ms and training 4536.8 ms per round, and explicitly says decomposition/projection happen once per round rather than per batch. The released `CustomCLIP.forward` invokes the prompt learner, whose forward unconditionally computes the SVD and projection. Its training path calls the model on each batch; there is no cached-round guard in these methods. The computation also precedes the training-mode branch.

This is a static call-path conflict, not a measurement of total overhead. The release might differ from the timed historical implementation, and no synchronized GPU timing or batch count was obtained. Multiplying the quoted milliseconds by an assumed number of batches would be unjustified. The remedy is to identify the timed implementation and counting unit, or measure the actual per-forward release. The historical Table 3 values remain Needs Evidence rather than established false measurements.
