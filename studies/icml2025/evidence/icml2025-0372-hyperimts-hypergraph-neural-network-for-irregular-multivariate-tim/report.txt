Abstract: The hypergraph construction, irregularity-aware similarity rule and published experimental scope are examined together with the migrated public implementation. The threshold described as learnable has no gradient path through its stated hard comparison. A separate indexing defect in the later vectorized implementation mixes observation embeddings across unequal-length batch members. Both findings are bounded to the demonstrated algorithm or release behavior; no historical benchmark impact is established. The source-specific assessment is Minor, with experiment-version provenance remaining unresolved.

# Identity and reviewed material

The original linked repository documents migration to PyOmniTS; the acquired current snapshot is commit `50a8b59bf922ff931275e5594538a865d7e9cb42`, 11 October 2026 [Retained latex: \cite{code}]. This later release is explicitly distinguished from the unknown version used in the 2025 experiments.

An IMTS sample contains observations \((t_j,z_j,u_j)\). The model predicts supplied future queries \((t_j,u_j)\), so access to future query timestamps and variable identities is part of the declared task, not by itself target-value leakage. In the inspected forward path, lines 89–96, target values are replaced by zeros before encoding; labels are retained separately for loss. The incidence matrices select timestamp and variable memberships. The attention complexity includes the \(M\times M\) node-attention term as the paper acknowledges, so reduced input padding does not imply linear complexity in the number of observations.

# Substantive findings

Problem 1 (The hard threshold is not learned by the stated differentiable path).  Section 4.2.2, p. 5, calls \(\delta\) a learnable threshold initialized at \(0.5\). Equations (10)–(11) use it only in the condition \(S_{\rm var}>\delta\) selecting whether to blend the aligned-observation score.

Write \(r=T_{\rm shared}/T_{\rm total}\) and fix the data and other parameters. Away from a tie, the rule is \[S(\delta)=S_{\rm var}+r(S_{\rm obs}-S_{\rm var})
\mathbf1\{S_{\rm var}>\delta,\ S_{\rm obs}\ne0\}.\] For each fixed pair, this is constant on either side of \(\delta=S_{\rm var}\); its derivative with respect to \(\delta\) is zero away from the switching point and generally undefined there. Subsequent softmax and MSE cannot supply a nonzero ordinary chain-rule derivative through this comparison. This does not say that other network weights cannot change the scores or switch branches.

The release confirms the issue: :683 creates `threshold` as a parameter, but lines 708–713 use it only in a Boolean greater-than comparison, then index assignments with that mask. There is no smooth relaxation, straight-through gradient, or explicit threshold-search rule in this module. Declaring a parameter trainable does not make a Boolean comparison differentiable.

For a concrete admissible pair, choose \(S_{\rm var}=0.8\), \(S_{\rm obs}=2\), \(r=1/2\) (one shared timestamp among two in the union) and \(\delta=0.5\). Dot-product embeddings can realize these positive scores. The blend is \(1.4\) at \(\delta\pm10^{-6}\), giving a centered finite-difference derivative of zero. At \(\delta=0.9\) the value is \(0.8\), demonstrating a gate whose position matters but receives no local gradient. The independent check records these values.

This is a supported inconsistency in the learnable-threshold description, assessed Minor: the principal hypergraph architecture and data-dependent switching still operate with a fixed threshold. A learned threshold would require a separately specified optimization mechanism; none is established by the reviewed material. Relabeling it as a fixed hyperparameter restores the literal description without proving any new forecasting result. A smooth gate would change the method and has not been evaluated. The presence of the full IAVD ablation in Table 3 is not evidence that this particular scalar learned.

Problem 2 (The later vectorized scatter can cross batch boundaries).  The current routine, lines 596–628, rebuilds aligned embeddings from a padded tensor of shape \(B\times M_{\max}\times d\). Its global `masked_scatter_` at line 623 consumes the flattened source consecutively without removing each sample’s padding. Unequal observation counts therefore break the intended within-sample correspondence.

Choose a batch of two samples, three timestamp slots, one variable and one retained embedding coordinate. Their valid counts are two and three. Nonnegative post-ReLU node embeddings and validity masks are \[X=\begin{pmatrix}10&20&0\\30&40&50\end{pmatrix},\qquad
M=\begin{pmatrix}1&1&0\\1&1&1\end{pmatrix}.\] These are exactly the batch-padding conditions produced by the earlier flattening operation. A source embedding dimension of three with time length three, for example, makes the routine retain one coordinate. The flattened source is \((10,20,0,30,40,50)\), and there are five true destinations. A global sequential scatter fills those positions from its first five elements, giving \[X_{\rm current}=\begin{pmatrix}10&20&0\\0&30&40\end{pmatrix},
\quad X_{\rm intended}=\begin{pmatrix}10&20&0\\30&40&50\end{pmatrix}.\] Thus the second sample loses its last embedding and receives a padding zero. The independent NumPy check implements the two mathematical index maps rather than importing author code. This already disproves the claimed observation correspondence; with multiple variables, the same flattened consumption can also misassign values to variable/timestamp positions.

The affected function is called at lines 577–586 to construct auxiliary similarity queries/keys for irregularity-aware attention. Correct pairing therefore matters to the central message-passing calculation. Equal-length batches, batch size one, or padding-free concatenated sources avoid this particular failure. The code explicitly labels the routine as speed-optimized since PyOmniTS v2.0.0, and the snapshot postdates publication by over a year. It would be unjustified to assign this defect to the original tables. The release defect is assessed Minor with historical influence Needs Evidence. A repair must filter each sample’s source to its valid count, or scatter per sample; the independent per-sample map restores the intended example. No full corrected implementation or model accuracy has been verified.

# Checked results, counterevidence and scope

The main numerical improvement quoted as up to \(11.4\%\) is consistent with Table 1: \((0.2454-0.2174)/0.2454=0.114099\) on MIMIC-IV. The source reports five seeds and explicitly notes differing preprocessing/normalization from earlier papers; this review does not reinterpret standard deviations as confidence intervals or establish statistical significance from the rounded table. Figure 3 was visually inspected for node/hyperedge information flow. Figure 4 was inspected at readable resolution: HyperIMTS has lower MSE but is not the fastest plotted model (50 ms versus GraFITi’s 33 ms), consistent with the text’s qualified efficiency wording. No universal speed superiority is inferred.

The forecast queries and target masks are allowed inputs under Eq. (1). The inspected encoding replaces future values with zero, so no target-value leakage was established. Other pipeline adaptations and every baseline implementation were not certified. Appendix A’s varied horizons and efficiency results were read but not reproduced or all visually inspected. No new data, author code execution, or training was used. OpenReview metadata was unavailable in the saved source-preparation receipt (403); discussion and later errata were not established.

# Conclusion

The two concrete concerns do not establish that the published forecasting rankings are false. The first limits the claimed trainability of one gate; the second demonstrates corruption in the later release’s aligned-embedding reconstruction. A historical commit and reruns on retained inputs are needed before assigning empirical consequences.
