Abstract: The published paper and its appendices were read in full, and its core public implementation was inspected statically. A supervised distance objective favors the opposite of the stated nearest-prototype assignment. The supplied release also lacks definitions needed by both advertised training stages. A printed Gaussian KL formula can be negative, although the inspected implementation uses the correct log-variance difference. Several comparative claims exceed the displayed results. These findings require local mathematical corrections, release repair and identification of the implementation used for the reported experiments; they do not establish that every reported accuracy is false. Scientific adjudication is pending.

# Supported findings

Problem 1 (The supervised distance term reverses the intended association).  Equation (15), p. 5, assigns each reconstructed feature to the nearest prototype, \(G_l=L_p[\arg\min Dis]\). Equation (20), p. 6, adds \(\|Dis-P_{gt}\|^2\), with the true class assigned one and every other class zero. Consequently, minimizing this term makes the true-class distance larger than the other distances, contrary to the claimed prevention of incorrect assignments.

The surrounding text calls the distances normalized, but specifies no decreasing distance-to-similarity transformation. The code removes that ambiguity: `diffusion_utils.py`, lines 359–396, computes raw squared Euclidean distances, uses `argmin`, then applies `mse_loss(distances, one_hot(labels))` at lines 388–392. With a one-dimensional reconstructed feature \(z=0\), true-class prototype \(l_0=1\) and wrong-class prototype \(l_1=0\), the distance vector is \((1,0)\). The supervised distance loss is exactly zero, the selected class is wrong, and both commitment terms in Equation (20) are zero because the selected prototype equals \(z\). Reversing the prototypes to obtain the correct nearest class gives distance vector \((0,1)\) and mean squared distance loss one. These values also hold for unsquared Euclidean distances in this particular example.

The term is on the intended training path: `FDM.forward`, lines 398–435, invokes the quantizer with labels and includes its loss dictionary; `model_utils.py`, lines 550–558, propagates the losses; `relation_head.py`, line 103, merges them into the returned loss dictionary; the trainer, line 186, sums that dictionary. The two-stage release failures below prevent claiming an observed training run, but do not change this static objective conflict.

This is Major because it directly contradicts the central mechanism claimed for supervised discretization. It is a counterexample to the effect attributed to this loss, not a proof that the full learned classifier must misclassify: reconstruction loss, other objectives and the learned output mapping can oppose or compensate for it. Replace the distance regression with a label-consistent objective, for example cross entropy on negative distances, or explicitly define a decreasing similarity and change the assignment rule consistently. Recheck quantization indices, class alignment, ablations and the affected results using the actual historical implementation. Simply changing the word “distance” is insufficient for the supplied code.

Problem 2 (The advertised public training path has unresolved definitions).  The supplied `scripts/train.sh` selects `NoDIS` and runs stages 1 and 2 with global, denoising and node-fusion flags enabled. In stage 1, `NoDIS.forward`, `model_utils.py` line 485, calls `self.VAE_decoder`; the supplied class neither creates nor defines that attribute. In stage 2, construction calls `FDM` at line 273, but that name is neither defined nor imported into the module.

The complete module was read, its top-level AST bindings checked, and all acquired Python sources searched for the relevant decoder and diffusion imports. The only `VAE_decoder` occurrence is the call. `FDM` exists in the separate diffusion module but is not imported into `model_utils`. The PENet constructor at predictor lines 135–138 and the Transformer constructor at lines 418–420 instantiate this very module. Thus, assuming dependencies, data and user-specified paths are otherwise supplied, the advertised stage-1 forward path has an unresolved attribute and the stage-2 constructor has an unresolved global name. These are static resolution findings; no author program was run to manufacture a traceback.

This is a Major obstacle to reproducing the core method from the supplied release. An omitted source file, an unpublished patch or a different historical version could explain it. No evidence supports extending the finding to an assertion that the paper’s original experiments did not run. Supply a version-complete release, import the diffusion class, define and document the missing decoder or remove its obsolete call consistently, and associate configurations and checkpoints with the reported tables. Repair may be local, but the two central stages cannot be reconstructed literally as published in this snapshot.

Problem 3 (The printed Gaussian KL expression is not a KL divergence).  Equation (18), p. 6, ends its summand with \(e^{\log v_c}-e^{\log v_p}\), where a log-variance difference is required. For equal means and variances \(v_c=3\), \(v_p=2\), its value is \(-0.25\).

For scalar Gaussians the correct direction \(D_{\rm KL}(N(m_c,v_c)\|N(m_p,v_p))\) is \[\frac12\left[\log\frac{v_p}{v_c}+\frac{v_c+(m_c-m_p)^2}{v_p}-1\right],\] which is approximately \(0.0472674\) in this example. `model_utils.py`, lines 435–441, uses the correct log-variance difference, providing substantive counterevidence against an implementation-wide KL error. The supported Minor finding is therefore a mathematical specification error. Correct the last two terms in the displayed formula and confirm that the historical implementation matches the inspected one.

Problem 4 (The head-preservation claim exceeds the displayed comparison).  Section 4.2, p. 8, says the method consistently achieves the best \(wmAP_{rel}\), \(wmAP_{phr}\) and weighted score on both Open Images versions. Fresh inspection of Table 2 corrects an initial-review transcription error: BGNN’s OI-V4 \(wmAP_{rel}\) is \(37.8\), so NoDIS’s \(38.21\) is higher. On OI-V6, \(wmAP_{phr}=38.95\) is compared with BCTR’s one-decimal \(39.0\); this nominal difference may reflect rounding and does not establish a strict deficit. Appendix B, p. 14, says head performance is maintained, while Table 6 gives VTransE head recall \(34.5\) versus \(30.05\) with NoDIS.

The supported Minor reporting overstatement concerns preservation of head performance; the initial Open Images counterexample is withdrawn. The head drop is \(4.45\) percentage points, while the corresponding body and tail recalls increase. The weighted Open Images scores independently recalculate to \(47.192\) and \(45.950\) from the displayed components and remain favorable. Acknowledge the displayed head/body/tail tradeoff and identify whether baseline configurations are matched. The reported precision does not establish strict Open Images superiority on every metric; neither does it establish the deficit asserted in the initial review.

# Mechanism and evidence checks

The dependency chain is coarse relation features and entity context, noisy refinement and prototype alignment, conditioned feature reconstruction, nearest-codebook mapping, and a learned prediction head fused with the backbone. Ground-truth prototype targets in Equation (12) and Algorithm 1’s repeated use of \(T_p\) make test-time notation ambiguous. However, the inspected implementation conditions on the full prototype table, while relation labels are passed to target and loss construction during training only; the relation-head wrapper sets labels to `None` at test time. A direct ground-truth predicate leak at inference was therefore not established. The algorithm should distinguish the full prototype table from a ground-truth-indexed training target.

Algorithm 1 also uses the original \(G'\) in its recurrence rather than the updated \(G_p\), and the code samples training timesteps differently from full-step inference. The published recurrence and the intended DDIM-inspired process need explicit reconciliation. This review does not assume that merely naming diffusion guarantees one particular sampler, nor does it elevate a schematic mismatch into an experimentally established failure. The current code also applies multiplicative noise where Equation (6) specifies additive noise; identifying the historical configuration is necessary before attributing performance to either variant.

Figures 1 and 7 show greater within-class feature variance after reconstruction and lower variance after discretization. The inspected analysis routine computes raw Euclidean variance. Multiplying every feature by \(\sqrt3\) triples this variance without adding semantic information, and mapping many features to one codebook vector mechanically reduces it. Thus these plots describe geometry but alone do not demonstrate improved class information, diversity useful for generalization, or preservation of rare semantic modes. Figures 8–9 and the source qualitative graphs were actually inspected; selected examples do not quantify selection bias or prove the claimed mechanism. No numerical plot digitization was performed.

The ablation arithmetic was checked: the joint NPR/PPA setting gives \(38.41\) versus \(36.16\) for PPA alone, a \(2.25\)-point difference; the joint loss setting gives \(38.41\) versus \(35.98\), a \(2.43\)-point difference; the diffusion/discretization comparison reports \(39.75\) versus \(38.41\), a \(1.34\)-point difference. A selected harmonic mean in Table 1 also agrees with its component recalls. These checks support the table arithmetic without verifying training runs, confidence intervals, selected checkpoints or raw predictions. The paper explicitly acknowledges that GQA results are not uniformly state of the art, and its other metrics trade ordinary recall against mean recall. Those qualifications should also govern the broader conclusions.
