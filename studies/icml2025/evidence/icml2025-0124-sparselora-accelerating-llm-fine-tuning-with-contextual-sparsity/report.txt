Abstract: The supplied paper gives substantial accuracy and efficiency comparisons and explicitly describes token, layer, and step sensitivity controls. The pinned implementation contains a core gradient-path defect: selected base-projection activations are gathered or scattered under `no_grad`, eliminating their backward contribution to upstream trainable adapters. The defect is demonstrated for the release, while its presence in the historical experiments remains unverified. A separate Minor issue concerns a table caption contradicted by its own category scores. Arithmetic checks support the headline ratios. Scientific adjudication is pending.

# Method and supported checks

The proposed computation preserves dense low-rank adapters while selecting channels in the frozen base projections, using low-rank SVD predictors and layer-specific sparsity. It keeps output tokens dense, delays sparsification by an initial dense interval, and applies dense inference after fine-tuning. These are empirical approximation choices; the paper does not prove that SVD selection exactly reproduces dense outputs or globally optimizes attention error.

The source registry explicitly returns `None` for LoRA adapter sparsity modes, consistent with the dense-adapter design. It assigns `out_scatter` to PEFT base layers for query, key, value, gate, and up projections, and `in_gather` to output and down projections. The Math10K script sets the initial dense fraction to \(0.05\), consistent with the relevant appendix configuration.

Independent arithmetic gives \[\frac{623+679}{384+436}=1.5878,\qquad \frac1{0.46}=2.1739.\] These agree, after rounding, with Figure 1’s approximately \(1.6\times\) combined forward/backward ratio and the approximately \(2.2\times\) FLOP reduction associated with Table 2. These calculations do not establish an independently measured wall-clock speedup.

# Problems

Problem 1 (Selected base-projection gradients are detached in the pinned implementation).  Assessment: Major for the core released implementation; historical experimental attribution Needs Evidence. Section 3 and Figure 3, p. 3, motivate sparse loss and gradient computation through selected base-model weights while retaining dense LoRA branches. The pinned `sparselora/modules/linear.py`, lines 19–22 and 30–40, instead performs activation gather and output scatter inside `torch.no_grad()` blocks. This removes the selected base path from reverse-mode differentiation.

## Exact paths and assumptions

The source path is not an unreachable utility. In `registry.py`, lines 33–47, a PEFT base projection is assigned `out_scatter` or `in_gather`. The API replaces eligible linear modules at `api.py`, lines 101–123. The attention module passes selected indices to those projections at `llama.py`, lines 71–88 and 104–108. In `linear.py`, lines 51–71, the patched adapter forward adds the base result to the dense LoRA result.

The finding assumes an enabled sparse layer with a nonempty proper subset of channels, a frozen base weight, and an input that depends on an upstream trainable adapter. These are ordinary fine-tuning circumstances. The selected index set can be held fixed locally; no derivative of a top-\(k\) decision is required.

For `out_scatter`, the selected matrix multiplication is initially differentiable with respect to its input. The subsequent `scatter_add` is evaluated under `no_grad`, so the assembled output loses that graph. For `in_gather`, the input gather itself is detached. Multiplication by a frozen base weight cannot restore the missing dependency. PyTorch’s primary documentation confirms that computations inside this context are excluded from the reverse-mode graph even when inputs require gradients. Neither gather nor scatter-add is a factory-function exception.

## Decisive derivative

Let an upstream scalar adapter parameter produce \(x(\theta)=(\theta,0)^\top\). Take frozen \(W=\operatorname{diag}(2,3)\) and retain channel 0. The intended selected base computation produces \(y=(2\theta,0)^\top\), with \[L(\theta)=\tfrac12\|y\|^2=2\theta^2,\qquad
 \left.\frac{dL}{d\theta}\right|_{\theta=1}=4.\] A fixed-index scatter or gather must preserve this derivative. Treating the selected result as detached gives contribution zero instead. An independent rational-arithmetic central difference at \(\theta=1\), with step \(10^{-6}\), is exactly \(4\). No author function was imported or executed, and this is not represented as a PyTorch runtime test.

The same reasoning applies if residual or LoRA branches are present: those branches can still carry gradients, but the selected frozen-base contribution is missing. Freezing a weight eliminates its own parameter update; it does not eliminate the Jacobian needed to train parameters preceding that weight.

## Counterevidence and impact limits

Keeping LoRA dense does permit learning, and dense tokens and other paths remain active. Thus this finding does not show that training completely stops, that all gradients vanish, or that any printed benchmark number is false. Deliberately using a stop-gradient approximation is another possible algorithm, but it is not the selected-weight backpropagation described in the paper and requires explicit characterization.

The acquired release is pinned, but no historical training commit or raw run log ties these exact lines to the reported experiments. That part of the conclusion is Needs Evidence. The release-level defect is nevertheless material: it changes the optimization mechanism and may reduce backward work beyond channel sparsification. It therefore affects both algorithmic fidelity and the interpretation of a speed measurement made with this implementation. Major is supported for the core implementation without requiring an observed accuracy loss.

The scoped correction is to leave mask prediction or index selection outside autograd if desired while retaining differentiable activation gather/scatter operations. This restores the selected base Jacobian. No source was modified, no repaired training run was performed, and neither corrected accuracy nor corrected speed is claimed.

Problem 2 (The MT-Bench all-category caption exceeds the displayed evidence).  Assessment: Minor. Table 4, p. 8, claims matching or exceeding LoRA across all categories. Its own entries instead decrease from \(5.50\) to \(5.45\) for Extraction, from \(2.25\) to \(2.20\) for Math, and from \(7.78\) to \(7.70\) for STEM.

The decisive check is subtraction of the reported entries, yielding \(-0.05,-0.05,-0.08\). The averages are consistent: the eight-category means are \(6.035\) for LoRA and \(6.0625\) for SparseLoRA. Thus the caption should say comparable aggregate performance, with mixed category changes. The decreases are small and no paired uncertainty information establishes statistical deterioration. This is a bounded reporting correction, not evidence against the core acceleration result.

# Additional evidence boundaries

## Aggregate definition

Table 3 lists nine GLUE tasks but its average is not the mean of all nine displayed columns: those means are \(82.7\) and \(84.2\). Excluding WNLI gives \(87.35\) and \(87.7375\), which approximately explain the printed \(87.3\) and \(87.7\); rounding of underlying scores may explain the first final digit. An eight-task aggregate is a plausible intended convention, but the exclusion should be specified. The relative direction of the reported comparison is preserved under either aggregation. This ambiguity is recorded separately from a proved core failure.

## Lossless performance and measurement scope

The paper reports five runs with highest and lowest discarded for the principal reasoning experiments (p. 6). Without raw runs, covariance, and a stated equivalence margin, small differences do not establish statistical equivalence. Conversely, small negative point estimates alone do not establish material harm.

The SVD factors are explicitly prepared offline (p. 5), while Table 8 measures online estimator overhead. The main timing evidence would be stronger with raw synchronized measurements and a clear inclusion list for warmup, data handling, offline setup, and dense initial steps. For example, if a sparse-step speedup is \(s\), an initial dense fraction \(f\) and one-time setup time \(T_0\) give total relative cost \[f+(1-f)/s+T_0/T_{\rm dense}.\] This identity is a scope check, not proof that the authors omitted any term. Precomputed factors can legitimately be amortized across runs. No timing falsification is inferred from absent logs.

# Overall assessment

The review supports a Major issue in the current source’s gradient path, with historical experiment attribution unresolved, and one Minor literal reporting issue. The headline ratios pass arithmetic checks. SVD approximation quality, task performance, and runtime remain empirical claims not independently reproduced here. The gradient correction must be tested before attributing the original performance–speed tradeoff to a repaired implementation.
