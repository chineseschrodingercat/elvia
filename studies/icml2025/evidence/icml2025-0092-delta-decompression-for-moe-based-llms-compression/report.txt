# 3. Problem 1 - static storage is confused with dynamic activity

Source claim. Section 3.5, p.5, explicitly labels its expression static parameter storage and gives (n*p+s/2)*P after static compression; the active expression is (k*p+s)*P. Section 3.4 and Algorithm 3, p.18, specify permanent pruning of half the target sparsity, followed by input-dependent skipping of the other half among retained columns. Table 12, p.16, fixes the throughput setting at 30% static plus 30% dynamic pruning, and the performance setting at 5% plus 5%.

Invalid step. A column skipped for one batch must remain available for a later batch that selects it. Dynamic skipping therefore cannot be treated as permanent removal. Independently of whether the ambiguous symbol p means retained or removed delta parameters, the printed base terms assign twice as many active base parameters as stored base parameters whenever s>0. That contradicts the specified subset relation. Reinterpreting the ratio convention alone cannot make both expressions correct.

\[P_{stored}=[nr+(1-s/2)]P,\qquad P_{active}=[kr+(1-s)]P.\] Complete realizable count. Choose n=8, k=2, 100-by-100 matrices (P=10,000), rank-25 delta factors of shapes 100-by-25 and 25-by-100 (5,000 parameters each, r=0.5), and s=0.6. Static pruning removes 30 of 100 columns, leaving 7,000 base parameters; each batch skips 30 more, leaving 4,000 active. A full-rank nonzero base and rank-25 deltas satisfy the architecture, and all counts are integers. Since r=0.5 is also the removed delta fraction, this example is unaffected by the paper’s ambiguous p convention. One algebraic realization sets the full-rank base to 2I, four experts to 2I+D and four to 2I-D, where D has 25 unit diagonal entries and all other entries zero, with equal positive Fisher weights. The weighted merge is the stated base and all deltas have rank 25. Calibration row norms can order the 100 base columns strictly, while a later input changes which 30 retained columns are dynamically skipped. This is an admissible parameter-count construction, not a claim about the Fisher statistics of a trained language model.

Quantity | Actual specified scheme | Printed expression

Stored compressed parameters | 8*5,000 + 7,000 = 47,000 | (8*0.5+0.6/2)*10,000 = 43,000

The storage compression in this example is 41.25%, not the printed expression’s 46.25%. The result follows directly from counts, independently of stochastic performance, Fisher values or which columns score lowest. The dynamic set can vary with input; no condition in the paper makes all dynamically omitted columns permanently unnecessary.

Connection to the reported resource budgets. The public cal_params.py, lines 191-211, counts all shared base matrices with factor (1-pp_ratio) in its total-parameter calculation. Its rank mapping is floor(H*I*r/(H+I)). With inspected Mixtral defaults H=4096, I=14336, L=32, n=8 and vocabulary size 32,000, an independent calculation gives 46.702792704B original parameters, 5.637144576B shared-base parameters and 1.605636096B unchanged parameters. No author calculator was run.

Counterevidence and limits. These are independent accounting results under the stated architecture and ratio definitions, not reproduced GPU-memory measurements. Alternative historical pruning configurations, offloading or storage formats require their own provenance. The released default pruning path retains full registered base tensors and slices temporary weights; that is additional release-level evidence, not proof of the hardware path behind Table 4. The public issue asking about compression hyperparameters is an unresolved question, not evidence of invalid experiments.

Impact: Major. The dependency is two-phase pruning -> persistent parameter allocation -> stated compression/memory budget -> performance comparisons at that budget. The incorrect resource accounting damages a central efficiency claim even if accuracy at the actual configuration survives. It does not refute delta decomposition or dynamic compute savings.

Precise scoped repair. Separate stored and active expressions. To match the table/helper budget [nr+(1-s)]P while storing the dynamically skipped columns, decrease delta retention by s/(2n); this applies only if the resulting retention is nonnegative and realizable after rank rounding. For n=8,s=0.6 the decrement is 0.0375, so the 0.1218 setting becomes approximately 0.0843. This does not match the different, literal printed static expression [nr+s/2]P. Matching that expression instead requires a decrement (1-s)/n, which is 0.05 in the small example. Both identities are verified below; neither is an empirical repair. Actual persistent storage must first be established, and changed ranks require fresh performance evaluation. Author adoption remains pending.

\[n\left(r-\frac{s}{2n}\right)+1-\frac{s}{2}=nr+1-s,\qquad n\left(r-\frac{1-s}{n}\right)+1-\frac{s}{2}=nr+\frac{s}{2}.\]

# 4. Problem 2 - Algorithm 5 changes the SVD objective

Source claim and discrepancy. Section 3.3, p.4, Eqs.6-8 defines S as a Cholesky factor of G=X*X^T and approximates D*S before inverse scaling. Appendix C.5, p.18, Algorithm 5 instead sets S=X*X^T directly. The original rendered p.18 confirms that this is present in the PDF, not extraction noise. These prescriptions are different [E2].

\[\|(D-A)X\|_F^2=\operatorname{tr}((D-A)G(D-A)^\top)=\|(D-A)S\|_F^2,\quad G=SS^\top.\] When G is positive definite, right multiplication by invertible S preserves rank. Truncating the SVD of D*S and undoing S therefore solves the activation-weighted rank constraint. Using G itself instead weights the squared error by G squared. The paper does not state a separate universal optimality theorem for Algorithm 5; the finding is the demonstrated non-equivalence of its recipe to the actual main method.

\[X=\operatorname{diag}(1,2),\quad D=\operatorname{diag}(3,1),\quad rank(A)\le1.\] All assumptions hold: dimensions are 2-by-2; G=diag(1,4) is positive definite; all inverses exist; retained rank 1 is valid; singular values are distinct. The Cholesky factor is diag(1,2). D*S=diag(3,2), so rank-one truncation returns A=diag(3,0). Its output squared Frobenius error is 4. Algorithm 5 uses D*G=diag(3,4), keeps the other direction and returns A=diag(0,1), whose output squared error is 9. The independent calculation confirms both ranks, reconstructions and errors.

Counterevidence and classification. The correct Cholesky construction is already stated in the main text. It is also implemented in preprocess/get_scale.py lines 46-69 and model/merge_mixtral.py lines 224-243. This confines the demonstrated error to a contradictory published algorithm specification; Minor is supported for this finding. The classification rests on that substantive counterevidence, not on appendix location, ease of repair or a requirement to show empirical degradation.

Scoped correction. First compute G=X*X^T, then S=chol(G) with G=S*S^T, and retain the existing SVD/inverse-scale steps. The proof above verifies the correction for G positive definite. Singular or regularized calibration matrices require an explicitly chosen regularization/pseudoinverse policy; no unverified universal fix is proposed.

# 5. Problem 3 - released perplexity evaluation omits later batches

Source and verified call path. D2-mixtral.py line 144 calls utils.ppl_eval_sharing. utils.py line 338 imports get_test_data; model/data_utils.py line 229 returns a loader with shuffle=False. Yet utils.py lines 61-62 create next(iter(data)) anew on every iteration. Each iteration therefore selects the first batch; the number of iterations does not provide dataset coverage.

Complete independent check. Consider two equal-length batches with deterministic average negative log-likelihoods log(2) and log(8). Correct full-data perplexity is exp((log(2)+log(8))/2)=4. Reinitializing the iterator visits batch indices [0,0] and yields perplexity 2. The reviewer replay uses only a Python list and arithmetic. Dynamic pruning could change predictions on the repeated batch, but cannot make subsequent batches enter this loop.

Judgment: Minor within the public-release scope, with potentially material evaluation consequences. This is a definite evaluation-path defect, not an unresolved interpretation of Python iterators. Its connection to the published benchmark numbers remains Needs Evidence because no run manifest binds those numbers to this source snapshot. A scoped repair is to traverse the loader once and accumulate loss by the actual nonignored target-token count. No published-score repair is claimed or applied. This inspected path is the perplexity call; the separate downstream run_lm_eval accuracy path is not shown to have the same iterator defect.

# 6. Problem 4 - released Fisher calibration shifts targets twice

Source and assumptions. preprocess/get_fisher.py lines 226-229 supplies tokens[:-1] as inputs and tokens[1:] as labels. It loads AutoModelForCausalLM at line 375. The pinned requirements specify Transformers 4.42.4; its stock MixtralForCausalLM shifts logits and labels internally at lines 1426-1434. The exact official dependency source was acquired and hashed, not executed [S4]. This finding concerns that documented stock Mixtral path. The script’s default model is mistralai/Mixtral-8x7B-v0.1 (line 495), but from_pretrained uses trust_remote_code=True and allows another base path. The conclusion is therefore explicitly confined to the documented stock Mixtral branch; custom loss behavior is not assumed.

Complete index check. Original tokens [0,1,2,3,4] become input [0,1,2,3] and supplied labels [1,2,3,4]. The internal shift compares outputs whose contexts end at [0,1,2] with targets [2,3,4]. Correct next-token targets for those contexts are [1,2,3]. Thus the squared gradients accumulated by the released Fisher routine come from a two-token-ahead objective. This is a source/index proof, not a claim about an observed model score.

Judgment: Minor release-objective error; published-run attribution and empirical damage are Needs Evidence. A custom model that deliberately omitted internal shifting would be a different path, and no such modification is assumed here. Supplying unshifted inputs and same-position labels to the stock causal model, with the intended masking, restores one next-token shift. That repairs alignment only; other Fisher approximations and resulting compression quality require their own verification.

# 7. Other checks, counterevidence and release scope

Fisher averaging: with nonnegative diagonal/per-coordinate Fisher weights whose sums are positive, Eq.5 is the minimizer of the corresponding weighted quadratic objective. The paper does not claim a new global optimality theorem for Fisher merging, guaranteed low rank of every delta matrix, or globally optimal multi-column pruning. The single-column norm product in Eq.9 equals that column’s rank-one output contribution norm; it does not require an unstated multi-column theorem.

Nonlinear forward interpretation: Eq.10 is valid as a normalized-gating identity for a shared linear projection. It should not be promoted into a claim that an arbitrary gated nonlinear FFN can be moved outside expert selection. The released Mixtral path retains shared-plus-delta projections inside the expert nonlinearity and disables the shared_infer option by default. This is counterevidence to an alleged mandatory linearization failure.

Empirical arithmetic: the displayed seven-task Mixtral D2-MoE means at 20% and 60% compression recompute to 0.60 and 0.52. Calibration, task evaluation and speed/memory claims were read but not reproduced. Table 7 associates base pruning 10% and delta removal 52.66% with perplexity 5.63, whereas Appendix A.5/Table 12 describe the 10% base configuration as selected and other tables report 5.28. This configuration-to-result provenance remains unresolved; no value is silently corrected.

Further bounded release deviations were retained without raising paper severity: cal_params.py lines 1120-1127 hardcode target/pruning values for the Mixtral helper despite parsing CLI options; the default ppwandasp scoring path uses a different weight moment from Eq.9. At equal unit activation norms, columns (1,1) and (1.3,0) score (sqrt(2),1.3) under Eq.9 but (sqrt(2),1.69) under the inspected release metric, reversing their ordering. These are static helper/metric discrepancies; no claim is made that the published calibration selected different channels. Full traces and the known open hyperparameter question are preserved in independent_code_notes.md.

# 8. Overall disposition and surviving results

The core shared-base/delta representation, the main-text Cholesky SVD method and possible reductions in arithmetic work survive this review. Published performance values may remain observations at their actual configurations. What fails is the demonstrated derivation connecting the stated dynamic pruning scheme to static storage and therefore to the nominal resource budget. A correct efficiency comparison must match persistent storage, active computation and hardware memory definitions separately.
