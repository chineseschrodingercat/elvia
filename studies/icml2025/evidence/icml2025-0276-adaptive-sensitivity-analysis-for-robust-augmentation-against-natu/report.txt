# Major: the active released sampler has a candidate-shape error

Problem 1 (Major, current-release core implementation).  The source constructs a distribution on pairs \((\text{augmentation name},\text{strength})\), but passes its list of two-tuples directly to an interface requiring a one-dimensional candidate population. When the current transform is invoked with that distribution, sampling raises a dimension error before applying the chosen augmentation.

The parent independently traced the following source dependency: `train.py`, lines 332–352, selects `RobustValLoop` for the proposed method. In `sensaug/loops.py`, lines 716–727, the sensitivity-derived distribution is built and passed to the training pipeline. Its keys are tuples at lines 625–646, including `("none",0)`. The unchanged dictionary reaches `RandomTrainTransformNew` through `sensaug/runner_utils.py`, lines 181–200. Finally `sensaug/dataset/augmentations.py`, lines 922–932, calls `np.random.choice` on the list of these keys.

For a complete admissible interface-level witness, use \[\mathcal{K}=[(\mathrm{rotate},0.2),(\mathrm{rotate},0.8),
                 (\mathrm{none},0)],\qquad
 p=(0.3,0.3,0.4).\] These are valid nonnegative probabilities summing to one and keys of the exact shape constructed upstream. The candidate array has shape \(3\times2\), not length-three scalar entries. Calling the installed NumPy legacy choice routine on this list yields \[\texttt{ValueError: a must be 1-dimensional}.\] The parent observed the same result in NumPy 2.3.5 in the isolated runtime and NumPy 2.4.3 in the authorized Windows runtime. The durable reviewer script records the latter version, candidate shape, exact exception, and inputs. No repository module was imported or called.

The blocker lies on the method’s core training augmentation path, not an ancillary plotting or cleanup routine. That direct dependency supports Major for the inspected release. The conclusion is conditional on reaching this transform with the distribution supplied by the inspected caller. It does not establish that the 2025 training runs used this release, failed, or produced invalid scores.

A precise local correction is to sample an integer index \(I\sim\operatorname{Categorical}(p)\), then retrieve the original tuple \(\mathcal{K}_I\). This preserves tuple types and categorical probabilities. A reviewer-authored index-selection check succeeds. The repository was not modified; no end-to-end repair is certified.

# Minor: a known sampling-direction description is reversed

Problem 2 (Minor; Figure 1 caption, page 1).  The caption states that worse-performing levels receive higher sampling probability. Algorithm 1 orders levels by descending accuracy and uses a beta-binomial PMF with parameters \(a=3/4,b=1\). That combination favors better-performing levels.

Direct cancellation in the beta-binomial PMF gives \[\frac{p_{i+1}}{p_i}=\frac{i+3/4}{i+1}<1.\] Thus the smallest rank has the largest probability. The default source flag and descending sort in `loops.py`, lines 393, 415, and 627–640, independently confirm this direction. The released README contains a correction dated 21 August 2026 explicitly acknowledging the caption reversal. This Problem is known issue reproduced, not a claim of new discovery. Algorithm 1 and the released PMF agree.

The README states that the PMF behavior produced the reported results. That historical assertion is attributed to the authors; it has not been independently verified from run records. No reversal of the implementation is proposed.

The omitted final bin is a related, disclosed behavior. With four returned interior levels, the five PMF masses for \(n=4\) are \[(2048,1536,1344,1232,1155)/7315.\] Only ranks \(0,\ldots,3\) are assigned to levels; the last mass, \(3/19\), flows to the clean-image entry. For \(m\) augmentation types, the source’s resulting clean probability is \[\frac{1+m(3/19)}{m+1}.\] For twenty types this is \(79/399\simeq0.197995\), rather than \(1/21\). Exact rational arithmetic verifies these values. This describes the constructed distribution; the sampler failure above prevents inferring an executed training frequency from it.

# Mathematical scope: valid spacing, additional assumptions

Let \(A(\alpha)\) be the endpoint-normalized accuracy drop and \(K(\alpha)\) the endpoint-normalized KID, with \(\alpha\in[0,1]\). The intended cumulative function is \[g(\alpha)=A(\alpha)-K(\alpha)+2\alpha.\] Appendix A refines the main-text \(1-MA(\alpha)\) to a clean-relative drop and describes normalization to endpoint two. The source’s `objective_function`, lines 273–299 of `sensitivity_analysis.py`, reflects this normalization, with machine epsilon in the denominators. Simply contrasting Equation (5) with the normalized source would omit this counterevidence.

For fixed endpoints \(g(0)=0,g(1)=2\), the appendix’s objective \(\max\min_{1\le i\le L}[g(\alpha_i)-g(\alpha_{i-1})]\) has upper bound \(2/L\) by telescoping. A continuous strictly increasing \(g\) attains it at equal \(g\)-increments. This conditional result is valid.

## What metric monotonicity does not establish

The stated justification that decreasing accuracy and increasing KID make \(g\) increasing is insufficient: KID is subtracted. A continuous example respecting both metric directions and normalized endpoints is \[MA(\alpha)=1-\alpha,\qquad
 K(\alpha)=\frac{\alpha}{10}
 +\frac9{10}\operatorname{clip}\bigl(5(\alpha-3/10),0,1\bigr).\] Here \(A(\alpha)=\alpha\), \(g(3/10)=87/100\), and \(g(1/2)=11/20\), a decrease. The actual \(L=5\) target \(4/5\) has three preimages, \[8/29,\quad 11/32,\quad 17/29.\] Exact rational calculations verify all three.

This refutes the stated implication, not the appendix’s explicitly added assumption that \(g\) is strictly increasing. Nor does it refute existence of equal-spacing solutions: continuity and fixed endpoints permit ordered first-crossing choices. The release takes the first PCHIP root at `sensitivity_analysis.py`, lines 396–400, so a selected-root interpretation is available. Whether actual curves satisfy the extra assumption is Needs Evidence. A claim that this witness disproves the conditional theorem or necessarily crashes root finding is unsupported.

Main Equation (4) minimizes over \(2\le i\le L\), whereas Appendix A includes the first interval from \(\alpha_0=0\). These objectives differ. For \(g(\alpha)=2\alpha,L=2\), Equation (6)’s points \((1/2,1)\) give the printed main objective value \(1\), while \((1/10,1)\) gives \(9/5\). The appendix and implementation use the endpoint-inclusive construction. This is recorded as a formalization clarification: the main equation should match the appendix before its optimality statement is applied.

Finally, PCHIP uncertainty is computed from roots after inserting synthetic upper/lower points. No established enclosure of the true curve or universal convergence bound was found. Positive endpoint drops, reliable KID denominators, and the realized inverse error remain unresolved conditions, rather than demonstrated failures of the reported benchmarks.

# Minor: the next-best comparator is not the best listed

Problem 3 (Minor; Appendix Table 7, page 14).  The caption reports a \(9.07\%\) relative ACDC mIoU improvement over the next-best method, identified as IDBH. The table gives Ours \(45.45\), IDBH \(41.67\), and VIPAug \(42.26\).

Independent arithmetic yields \[100(45.45-41.67)/41.67=9.0713\%,\] but the best listed comparator is VIPAug, giving \[100(45.45-42.26)/42.26=7.5485\%.\] The improvement and first-place ranking survive; the next-best margin should be approximately \(7.55\%\). Main Table 2’s fog, rain, and snow relative gains agree to rounding.
